- Hematology uses hematologyDifferential with instrument_value as immutable input; differential_type affects reports only and hides only EMPTY cells the device does not count (differentialReportRows); any typed or received value always prints. Why: all devices share the same rules without redistributing received counts.
- Hemogram calculation lives ONLY in the parameter formula (CALC): no hidden/default formulas in code; CALC on + empty formula calculates nothing; bands (%) can never be calculated; a manually typed differential replaces the whole instrument differential and must sum 100% or release is blocked (blockRelease). Only differential PERCENTS (differentialPercent) go through resolveDifferential; absolutes (/mm³) always follow their CALC formula. Why: the lab must see and control every calculation per client.
- Reference ranges are picked by pickReference comparing the patient's completed age in each range's own unit (dias/semanas/meses/anos via ageInUnit from PatientCtx.birthDate), falling back to whole years only without a birth date; callers must pass birthDate. Why: neonatal/infant ranges need days and months, and year-only catalogs keep their old boundaries.
- A parameter without its own ranges may borrow exam-level reference_values only by its id prefix ("<paramId>-n", examLevelRangesFor); legacy unprefixed exam ranges apply only to single-parameter exams. LaudoDocument infers Série Vermelha/Branca/Plaquetas titles only for hemogram exams (isHemogramExam). Why: other exams (e.g. Fluxo Vaginal, urine) printed another field's reference and blood-series titles.
- 3-part hematology estimate (ajusteDiferencial3Partes) runs only when lab_settings.hemo3p_estimativa_ativa is on (Ielmo only), from hidden MID/Granulocyte params, below the WBC limit and without a manual slide; saved rows use source 'estimado_3_partes', and with the switch on, slide or estimate makes differential absolutes follow their formula. Why: pilot per company, other companies untouched.
