- Attendance edit (Detalhes Atendimento ⋮ → Editar) reuses the Cadastro steps LabStep2ExamData/LabStep3GuidesProcedures over a fresh order row and saves only changed columns via editarAtendimento; exams with typed results cannot be removed. Why: same form as Cadastro and the audit trigger logs exact changes.
- Tube sample codes use attendance_orders.empresa_seq, frozen by trigger at insert and never overwritten; client/edge read it from the order, session sequence_id is only a fallback. Why: labels and instruments must never compute different codes.
- Order numbers (attendance_orders.order_number) are unique per company across all origins: next_attendance_order_number counts by number suffix company-wide and trigger attendance_orders_numero_unico refuses repeats; Mudar origem only changes origin fields, never the number; receive-instrument-result/graphic refuse a barcode whose order number is shared by another active order (_shared/pedidoRepetido), and lab screens group exams by order id, not number. Why: moving an order made the old origin reissue its number to another patient, so tubes and results could reach the wrong patient.
- Label search (Busca de Atendimentos and lab Análise) goes only through lib/buscaEtiqueta: an exact tube alphanumeric code or sample code shows only that order and ignores the period filter; the digits-only fallback runs only when the text has no letters. Why: pasting a label must never list unrelated orders.
