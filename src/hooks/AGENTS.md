- Attendance orders: lists read through useAttendanceCadastro (explicit LIST_COLUMNS, 1,000-row blocks via buscarEmBlocos, optional server-side created_at range and status include/exclude); work queues filter pending statuses server-side with no date limit, completed orders load only for the screen's own period/search; screens that only write use useAttendanceOrderActions; every write refreshes via invalidating the ['attendance_orders', companyId] prefix; the sidebar counts with its own light status query. Why: avoid refetching full lists, never lose rows to the 1,000-row cap, keep old pending items visible.
- Realtime subscriptions go only through useCanalRealtime (unique channel suffix, removeChannel on unmount/deps change, always filtered by company/unit, paused when the tab is hidden > 2 min and resumed with one reload via aoRetomar; manterEmSegundoPlano only for screens whose background alerts depend on it). Why: forgotten tabs held database connections and overloaded login at peak times.
- Idle logout lives only in useIdleLogout/IdleLogoutGuard (mounted once in App, acts on authenticated routes; values in src/lib/sessaoInatividade.ts; pending writes counted by requisicoesPendentes). Why: staggered per-user timeouts avoid mass logouts and never interrupt a save.
